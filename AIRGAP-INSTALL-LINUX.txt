CI Cyber Lab -- Air-gap install instructions (Linux)
====================================================

TL;DR -- two commands, one per box
----------------------------------

  Online (internet) Linux box, from the repo root:
      ./airgap.sh pack
      (defaults to <parent-of-repo>/ci-cyber-lab-bundle; -o <path>
       for elsewhere.)

  Air-gapped Linux box, from the bundle, as root/sudo:
      sudo ./airgap.sh install -s /path/to/bundle \
                               -t /opt/ci-cyber-lab --seed

  Refresher at the console:  ./airgap.sh help

Both boxes are Linux x86_64. Bash 4+ is fine (any modern distro).
Move the bundle between boxes however your IA policy allows: USB,
tarball over removable media, scp through a one-way data diode, etc.


--------------------------------------------------------------------
PHASE 1 -- Build the bundle on the ONLINE box
--------------------------------------------------------------------

Prereqs on the online box:
  - Node.js >= 20.11    (https://nodejs.org)
  - Git
  - curl, tar, rsync    (universal; reinstall via apt/dnf if missing)
  - The repo cloned somewhere local

Steps:

  1. cd into the repo root (where airgap.sh lives).

  2. Run:

       ./airgap.sh pack
       ./airgap.sh pack -o /media/usb/ci-cyber-lab-bundle   # custom path

     What it does:
       - downloads the Node.js Linux x64 tarball  (~30 MB)
       - installs pnpm globally via npm (no admin needed for
         nvm-managed Node; needs sudo if Node is in a system path)
       - runs pnpm install + prisma generate + a production build
       - copies the repo + node_modules into the bundle directory
       - writes manifest.json + INSTALL.txt into the bundle root

     Expect 5-20 minutes.

  3. When you see "Bundle complete", the bundle is ready to carry.


--------------------------------------------------------------------
PHASE 2 -- Install on the OFFLINE box
--------------------------------------------------------------------

Prereqs on the offline box:
  - Root / sudo access for /opt + the Node symlinks.
  - PostgreSQL installed and running locally.

      Debian/Ubuntu:
          apt install postgresql postgresql-client
      RHEL/Rocky/Fedora:
          dnf install postgresql-server postgresql
          postgresql-setup --initdb
          systemctl enable --now postgresql

      Then set the postgres user's password (one-time):
          sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD 'YOUR_PASSWORD';"

      Then create the application database (one-time):
          sudo -u postgres psql -c "CREATE DATABASE ci_cyber_lab;"

  - rsync, tar (almost always preinstalled).

Steps:

  1. Make the bundle visible to the offline box (mount the USB,
     copy with scp, etc.).

  2. Run:

       sudo ./airgap.sh install \
           -s /path/to/bundle \
           -t /opt/ci-cyber-lab \
           --seed

     What happens, in order:

     a. Node.js is extracted to /opt/node-vX.X.X-linux-x64/ and
        symlinked into /usr/local/bin/{node,npm,npx}. (Use
        --skip-node if Node is already installed.)

     b. The script verifies psql is available. (Use
        --skip-postgres-check if you really know what you're
        doing -- e.g. using a remote DB.)

     c. The repo copies to /opt/ci-cyber-lab.

     d. The script prompts for DATABASE_URL. Paste something like:

          postgresql://postgres:YOUR_PASSWORD@localhost:5432/ci_cyber_lab

     e. Prisma migrations apply against that DATABASE_URL. Prisma
        is idempotent -- already-applied migrations are skipped.

     f. If --seed was passed, the seed script populates the
        curated challenge catalog. Skip the flag and run later:

          cd /opt/ci-cyber-lab/apps/api
          node dist/scripts/seed.js


--------------------------------------------------------------------
PHASE 3 -- Start the platform
--------------------------------------------------------------------

For a quick verification:

  API (port 4000):
      cd /opt/ci-cyber-lab/apps/api
      node dist/main.js

  Web (port 3000):
      cd /opt/ci-cyber-lab/apps/web
      node node_modules/next/dist/bin/next start -p 3000

Open http://localhost:3000 in a browser on the same box.

First admin account:
  The seed step creates an admin with deterministic default
  credentials so you don't have to dig through scrollback:

      Email:    admin@example.local
      Password: CICyberLab-Admin-1

  CHANGE THE PASSWORD IMMEDIATELY on first login -- this is a
  known default. Rotate via the admin profile menu in the web
  app, or from the shell:

      cd /opt/ci-cyber-lab/apps/api
      node dist/scripts/reset-password.js \
          --email admin@example.local \
          --password '<new-password>'

  Override the seeded defaults at install time:

      sudo ./airgap.sh install ... --admin-email you@org.local \
                                    --admin-password 'YourPassword123'

To run as systemd services (recommended for anything beyond a
quick test), create two unit files under /etc/systemd/system/:

    # /etc/systemd/system/ci-cyber-lab-api.service
    [Unit]
    Description=CI Cyber Lab API
    After=network.target postgresql.service
    Requires=postgresql.service

    [Service]
    Type=simple
    User=ci-cyber-lab
    WorkingDirectory=/opt/ci-cyber-lab/apps/api
    EnvironmentFile=/opt/ci-cyber-lab/apps/api/.env
    ExecStart=/usr/local/bin/node dist/main.js
    Restart=on-failure
    RestartSec=5

    [Install]
    WantedBy=multi-user.target

    # /etc/systemd/system/ci-cyber-lab-web.service
    [Unit]
    Description=CI Cyber Lab Web
    After=network.target ci-cyber-lab-api.service

    [Service]
    Type=simple
    User=ci-cyber-lab
    WorkingDirectory=/opt/ci-cyber-lab/apps/web
    ExecStart=/usr/local/bin/node node_modules/next/dist/bin/next start -p 3000
    Restart=on-failure
    RestartSec=5

    [Install]
    WantedBy=multi-user.target

Create the service user, fix ownership, enable both:

    useradd -r -d /opt/ci-cyber-lab -s /usr/sbin/nologin ci-cyber-lab
    chown -R ci-cyber-lab:ci-cyber-lab /opt/ci-cyber-lab
    systemctl daemon-reload
    systemctl enable --now ci-cyber-lab-api ci-cyber-lab-web


--------------------------------------------------------------------
Parameter reference
--------------------------------------------------------------------

Every parameter airgap.sh takes, grouped by which mode uses it.
Long form (--name) and short form (-x) work interchangeably.

COMMON
  pack | install | help
      First positional argument. What the script should do. With no
      argument the script prints a banner and exits.
  -h, --help
      Print usage. Same effect as `help`.

PACK MODE   (online box)
  -o, --output <path>
      Where to write the bundle.
      Default: <parent-of-repo>/ci-cyber-lab-bundle

INSTALL MODE   (air-gapped box, run as root/sudo)
  -s, --source <path>     REQUIRED. Where the bundle lives.
  -t, --target <path>     REQUIRED. Where the platform should live
                          on disk.
  --seed                  Run the seed script after migrations apply.
                          The curated challenge catalog lands in the
                          DB.
  --skip-node             Skip the Node.js extract+symlink step. Use
                          when Node >= 20.11 is already on the box.
  --skip-postgres-check   Skip the `which psql` precheck. Use when
                          Postgres lives on a different host (remote
                          DATABASE_URL).
  --force-repo-copy       Re-copy the bundle's repo over -t even if
                          -t already has a built repo. Default skips
                          the copy on re-runs (faster troubleshooting).
  --admin-email <email>   Email for the seeded admin account.
                          Default: admin@example.local
  --admin-password <pw>   Password for the seeded admin account.
                          Default: CICyberLab-Admin-1
                          Both are seed-time only -- change AFTER
                          first login via the web UI or
                          reset-password.js (see Phase 3).
  --api-port <int>        Port the printed start command tells you to
                          bind the API to. Default 4000.
  --web-port <int>        Same idea for the web server. Default 3000.

                          DOCUMENTATION ONLY -- the script does not
                          start services, so if you pass these you
                          also have to use the same port when you
                          run `node dist/main.js` / `next start` (or
                          in the systemd unit's ExecStart).


--------------------------------------------------------------------
What the script does NOT automate (intentionally)
--------------------------------------------------------------------

Operator-policy decisions:

  - Installing PostgreSQL and choosing the postgres password.
  - Creating the application database (CREATE DATABASE ...).
  - Opening firewall rules (default install binds to localhost).
  - TLS termination (none configured; use nginx, Caddy, or your
    org's reverse-proxy of choice in front of the API + web).
  - Backups of the Postgres data dir and any artifact storage
    folder under /opt/ci-cyber-lab/apps/api/data (or wherever
    ARTIFACT_STORAGE_ROOT points).


--------------------------------------------------------------------
Troubleshooting
--------------------------------------------------------------------

"command not found: pnpm" during pack
  The script will `npm install -g pnpm@9.12.0` automatically.
  If that fails, your npm global prefix may not be writable --
  check with `npm config get prefix`. If it returns a system
  directory you can't write to, set a user-writable one:
      npm config set prefix "$HOME/.npm-global"
      export PATH="$HOME/.npm-global/bin:$PATH"
  then re-run pack.

"prisma migrate deploy" fails with "database does not exist"
  You skipped the CREATE DATABASE step in Phase 2 prereqs.
  Create it manually with:
      sudo -u postgres psql -c "CREATE DATABASE ci_cyber_lab;"
  then re-run install -- it's idempotent.

Web app build fails with native-module errors mid-install on the
target box
  The bundle was built on a glibc version newer than the target's.
  Build the bundle on a host that matches the target's libc
  (e.g. pack on an Ubuntu 22.04 host if installing on Ubuntu 22.04)
  and re-run.

systemd service won't start with EACCES
  The ci-cyber-lab user can't read /opt/ci-cyber-lab. Re-run:
      chown -R ci-cyber-lab:ci-cyber-lab /opt/ci-cyber-lab

Anything else
  manifest.json in the bundle root captures the Node URL, repo
  commit, and pack time -- useful for filing a bug.
