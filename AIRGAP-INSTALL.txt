CI Cyber Lab -- Air-gap install instructions (Windows)
======================================================

**********************************************************************
**                                                                  **
**   PREFER NTFS FOR THE WORKING REPO.                              **
**                                                                  **
**   Clone the repo to your C:\ drive (or another NTFS / ReFS       **
**   volume) before running airgap.ps1 -Mode Pack. FAT32 / exFAT    **
**   will probably work -- the script passes                        **
**   --config.node-linker=hoisted so the BUNDLE doesn't need        **
**   symlinks -- but pnpm's content-addressable store still uses    **
**   NTFS hardlinks under the hood, so half-finished installs on    **
**   a USB stick remain a common failure mode. The script will      **
**   surface a warning (not an abort) if it sees one.               **
**                                                                  **
**   The BUNDLE (-Output) can live on any filesystem; only the      **
**   working repo matters for this.                                 **
**                                                                  **
**       cd C:\                                                     **
**       git clone <repo-url> platform                              **
**       cd C:\platform                                             **
**       .\airgap.ps1 -Mode Pack -Output E:\ci-cyber-lab-bundle     **
**                                                                  **
**   Check a drive's filesystem:                                    **
**       (Get-Volume -DriveLetter E).FileSystemType                 **
**                                                                  **
**********************************************************************


TL;DR -- two commands, one per box
----------------------------------

  Online box, from the repo root:
      .\airgap.ps1 -Mode Pack
      (defaults to <repo-drive>:\ci-cyber-lab-bundle; -Output <path>
       for elsewhere.)

  Air-gapped box, elevated PowerShell, from the USB:
      .\airgap.ps1 -Mode Install -Source E:\ci-cyber-lab-bundle `
                                 -Target C:\ci-cyber-lab -Seed

  Refresher at the console:  .\airgap.ps1  (prints a banner.)

Both boxes are Windows. PowerShell 5.1 (built in to Win 10/11) is fine.


--------------------------------------------------------------------
PHASE 1 -- Build the bundle on the ONLINE box
--------------------------------------------------------------------

Prereqs:
  - Node.js >= 22.12   (https://nodejs.org)
  - Git                (https://git-scm.com)
  - The repo cloned to an NTFS drive (see banner above)
  - A USB drive with at least 5 GB free

Steps:

  1. Plug in the USB. Note the drive letter (e.g. E:).

  2. Open PowerShell, cd to the repo root (where airgap.ps1 lives).

  3. Run:

       .\airgap.ps1 -Mode Pack

     What it does:
       - downloads the Node.js MSI       (~30 MB)
       - downloads the PostgreSQL EXE    (~300 MB)
       - runs pnpm install + prisma generate + a production build
       - copies the repo + node_modules into the bundle directory
       - writes manifest.json + INSTALL.txt into the bundle root

     Expect 10-30 minutes.

  4. When you see "Bundle complete", eject the USB.

Optional overrides:
  -NodeMsiUrl <url>           Newer Node LTS MSI
  -PostgresInstallerUrl <url> Different Postgres major version


--------------------------------------------------------------------
PHASE 2 -- Install on the OFFLINE box
--------------------------------------------------------------------

Prereqs:
  - Local administrator rights
  - At least 5 GB free under C:\ (or wherever you point -Target)

Steps:

  1. Plug the USB in. Note its drive letter (e.g. E:).

  2. Open PowerShell AS ADMINISTRATOR (right-click PowerShell -> "Run
     as administrator"; confirm the title bar says "Administrator").

  3. If PowerShell refuses unsigned local scripts, allow this session:

       Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

  4. From the USB:

       cd E:\ci-cyber-lab-bundle\repo
       .\airgap.ps1 -Mode Install -Source E:\ci-cyber-lab-bundle `
                                  -Target C:\ci-cyber-lab -Seed

     What happens, in order:

     a. Node.js installs silently. (-SkipNode if it's already there.)

     b. The PostgreSQL installer opens. It's interactive on purpose:
        you choose the postgres-user password.

        REMEMBER THE POSTGRES PASSWORD. You'll paste it into a
        DATABASE_URL in step (d).

        (-SkipPostgres if a Postgres server is already running here.)

     c. The repo copies to -Target. This includes a pre-built
        node_modules, so the offline box never resolves npm packages.

     d. The script prompts for DATABASE_URL. Paste something like:

          postgresql://postgres:YOUR_PASSWORD@localhost:5432/ci_cyber_lab

        If the database doesn't exist yet, create it in another
        PowerShell:

          & "C:\Program Files\PostgreSQL\16\bin\psql.exe" `
            -U postgres -c "CREATE DATABASE ci_cyber_lab;"

     e. Prisma migrations apply. Idempotent -- safe to re-run.

     f. If -Seed was passed, the curated challenge catalog is seeded.
        To seed later instead:

          cd C:\ci-cyber-lab
          node apps\api\dist\scripts\seed.js


--------------------------------------------------------------------
PHASE 3 -- Start the platform
--------------------------------------------------------------------

The easiest path: the install writes a start.ps1 helper into
-Target. It launches both services in their own PowerShell
windows, baking the install-time ports as defaults:

      cd C:\ci-cyber-lab
      .\start.ps1
      # or, override the ports for THIS run:
      .\start.ps1 -ApiPort 4000 -WebPort 9300

Pass -AutoStart on the install itself to launch them immediately
after the install completes (no manual start needed for the first
run):

      .\airgap.ps1 -Mode Install -Source ... -Target ... -Seed -AutoStart

The two new PowerShell windows survive after the install command
exits, so you can close the parent and the services keep running.
Stop them by closing the new windows.

PORT CONFLICTS: if the default port 3000 is already in use on the
target box (NAS web UI, dev tools, etc.), pass -WebPort to bind
the web app somewhere else. The setting flows through to start.ps1.

      .\airgap.ps1 -Mode Install -Source ... -Target ... -Seed -WebPort 9300

For production-style deployment (running as a service, surviving
logoff, auto-restart on crash) the script does NOT register
Windows services -- that's an operator policy choice (NSSM,
scheduled task, or a service account). For a manual quick
verification:

  API (port 4000):
      cd C:\ci-cyber-lab\apps\api
      $env:PORT = 4000
      node dist\main.js

  Web (port 3000):
      cd C:\ci-cyber-lab\apps\web
      node node_modules\next\dist\bin\next start -p 3000

Open http://localhost:3000 on the same box -- you should see login.

First admin account:
      Email:    admin@example.local
      Password: CICyberLab-Admin-1

CHANGE THE PASSWORD IMMEDIATELY on first login -- this is a known
default. Rotate via the admin profile menu, or from PowerShell:

      cd C:\ci-cyber-lab\apps\api
      node dist\scripts\reset-password.js `
          --email admin@example.local `
          --password '<new-password>'

Override the seeded defaults at install time:

      .\airgap.ps1 -Mode Install ... -AdminEmail you@org.local `
                                     -AdminPassword 'YourPassword123'


--------------------------------------------------------------------
Parameter reference
--------------------------------------------------------------------

Every parameter airgap.ps1 takes, grouped by which mode uses it.

COMMON
  -Mode <Pack|Install|Help>
      What to do. Omitted -> the script prints a banner and exits
      (no interactive prompt).

PACK MODE   (online box)
  -Output <path>
      Where to write the bundle.
      Default: <repo-drive>:\ci-cyber-lab-bundle
  -NodeMsiUrl <url>
      Override the Node.js Windows-x64 MSI to download. Default is
      Node v22.12.0, the first LTS where `require(esm)` is on by
      default -- the seed step needs it because @ci-train/contracts
      is ESM. Bump only if you want a newer LTS; do NOT downgrade
      below 22.12.
  -PostgresInstallerUrl <url>
      Override the PostgreSQL Windows-x64 installer to download.
      Default is PostgreSQL 16.4. Bump if you want a different
      major version.

INSTALL MODE   (air-gapped box, elevated PowerShell)
  -Source <path>          REQUIRED. Where the bundle lives (USB root).
  -Target <path>          REQUIRED. Where the platform should live
                          on disk.
  -SkipNode               Skip the silent Node MSI. Use when Node is
                          already installed.
  -SkipPostgres           Skip the Postgres installer. Use when a
                          Postgres server is already running here --
                          you'll still be prompted for DATABASE_URL.
  -Seed                   Run the seed script after migrations apply.
                          The curated challenge catalog lands in the DB.
  -ForceRepoCopy          Re-copy the bundle's repo over -Target even
                          if -Target already has a built repo. Default
                          skips the copy on re-runs (faster
                          troubleshooting).
  -AdminEmail <email>     Email for the seeded admin account.
                          Default: admin@example.local
  -AdminPassword <pw>     Password for the seeded admin account.
                          Default: CICyberLab-Admin-1
                          Both are seed-time only -- changing them
                          AFTER first login goes through the web UI or
                          reset-password.js (see Phase 3).
  -ApiPort <int>          Port the API binds to. Default 4000.
                          Flows through to: the printed start commands,
                          the generated start.ps1's default, and the
                          auto-start spawn if -AutoStart is set.
  -WebPort <int>          Same idea for the web server. Default 3000.
                          Override if the default conflicts with
                          another service on the box (NAS web UI, etc.).
  -AutoStart              After the install completes, immediately
                          launch the API + web in their own PowerShell
                          windows via the generated start.ps1. Without
                          this, start.ps1 still gets written -- the
                          operator just has to run it manually.


--------------------------------------------------------------------
What the script does NOT automate (intentionally)
--------------------------------------------------------------------

Operator decisions that vary too much site-to-site:

  - The postgres-user password.
  - Where Postgres puts its data directory.
  - Windows Firewall rules. By default both services bind to
    localhost only -- safe for a single-box install. Open ports
    only if other hosts on the LAN need to reach the web app.
  - Running the API + web as a service (NSSM, scheduled task,
    sc.exe -- pick what your IA / sysadmin policy requires).
  - TLS termination (none by default -- IIS or Caddy in front of
    the API + web if you want HTTPS).
  - Backups: the Postgres data directory and the artifact storage
    folder under C:\ci-cyber-lab\apps\api\data (or wherever
    ARTIFACT_STORAGE_ROOT points).

README.md and CLAUDE.md in the repo cover environment variables
in more depth.


--------------------------------------------------------------------
Troubleshooting
--------------------------------------------------------------------

"running scripts is disabled on this system"
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
  in the same PowerShell window, then re-run airgap.ps1.

"Node MSI returned 1603" during install
  1603 = MSI's generic fatal-install error. Causes, in order:
    - Node already installed. The script auto-detects and skips
      the MSI; if you hit this on an older script version, pass
      -SkipNode.
    - A pending Windows reboot. Reboot, then re-run.
    - An MSI custom-action failure. Open the install log at
      %TEMP%\ci-cyber-lab-node-msi.log and search "Return value 3" --
      the line above names the failing action.

"corepack: command not found" during pack
  Reinstall Node.js >= 22.12 from nodejs.org; corepack ships with it.

"Node vXX.YY.Z is too old" during install
  The script aborts before migrations apply if the Node on PATH is
  older than 22.12.0. ci-cyber-lab requires Node 22.12+ because
  @ci-train/contracts is ESM and the seed step requires it from
  CommonJS -- only Node 22.12+ has `require(esm)` on by default;
  earlier Node aborts seed.js with ERR_REQUIRE_ESM.

  To fix on the air-gapped box:

    1. Install Node from the bundle (overwrites C:\Program Files\nodejs\):

         Start-Process msiexec.exe -ArgumentList @(
           '/i', 'E:\ci-cyber-lab-bundle\installers\node.msi',
           '/qn', '/norestart', 'ADDLOCAL=ALL') -Wait

    2. Open a FRESH PowerShell so PATH picks up the new node,
       confirm with:  node --version

    3. Re-run airgap.ps1. Migrations are idempotent; seed will retry.
       If migrations had already applied on a previous failed run,
       add -SkipNode (the bundled node is now first on PATH).

  Or uninstall the old Node via Add/Remove Programs first and
  re-run airgap.ps1 without -SkipNode.

"ERR_REQUIRE_ESM" / "require() of ES Module" during seed
  Same root cause as above. The pre-flight version check should
  catch this before migrations run, but if you somehow get here
  (e.g. an older script version), the recovery is identical.

"The term 'pnpm' is not recognized" during pack
  The script tries `npm install -g pnpm@9.12.0` automatically. If
  THAT step fails, check `npm config get prefix` returns a directory
  on your PATH (default %APPDATA%\npm is). Then re-run Pack.

"pnpm install" pulls something during pack and fails
  Online box behind a corporate proxy. Set HTTPS_PROXY / HTTP_PROXY
  before running airgap.ps1.

prisma migrate deploy fails with "database does not exist"
  Create it once with psql (Phase 2 step d), then re-run Install
  with the same -Source and -Target.

"EADDRINUSE :::3000" / web app refuses to start on the default port
  Something else on the box is already listening on 3000 (a NAS
  admin UI, a stale next.js process from a prior install attempt,
  a dev tool). Three ways to fix it:

  1. (Fastest) Run start.ps1 with a different port for THIS launch:

         cd C:\ci-cyber-lab
         .\start.ps1 -WebPort 9300

     Then browse to http://localhost:9300. start.ps1 keeps the
     install-time default; this only changes the current run.

  2. (Persistent) Re-run the install with a new -WebPort. The
     migrations and seed are idempotent, so this just rewrites
     start.ps1 with the new default baked in:

         .\airgap.ps1 -Mode Install -Source E:\ci-cyber-lab-bundle `
                                    -Target C:\ci-cyber-lab `
                                    -Seed -WebPort 9300 -AutoStart

  3. (Free the port) Find what's holding port 3000 and stop it:

         Get-NetTCPConnection -LocalPort 3000 -State Listen |
             Format-Table -AutoSize OwningProcess
         Stop-Process -Id <pid-from-above> -Force

     Useful only if the holder is actually a stale process and
     not a service you depend on (a NAS web UI generally is).

Postgres installer hangs or won't start during install
  The Bitrock installer is sensitive to weird console states. Run
  it directly:
      E:\ci-cyber-lab-bundle\installers\postgresql.exe
  then re-run airgap.ps1 with -SkipPostgres.

Anything else
  manifest.json in the bundle root captures the Node URL, Postgres
  URL, repo commit, and pack time -- useful for filing a bug.
